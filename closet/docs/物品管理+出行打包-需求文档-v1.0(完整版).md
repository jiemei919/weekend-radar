## 一、背景与问题

- **现状**：洁梅用一份离线 Excel 记录春/夏/秋/冬的衣物、鞋、配饰、包等（已迁移为 **299 件结构化数据 + 8 条心愿**，存 `Obsidian Vault/物品库/`，并已在 `travelling/closet/` 落地 `items.json` 等）。该路径处于 iCloud「桌面与文稿」同步范围，数据已在洁梅 iCloud 2TB 上，无需迁移、天然私有。
- **关键环境事实**：洁梅的 Mac 放在公司、不在家，非工作日/下班合盖即休眠；家人手机在家用 WiFi 或出门用 4G 均处于"公司网络之外"，无法直接连到公司 Mac。
- **记录发生的真实时机**：洁梅记录"买了/丢了/卖了"**绝大多数发生在 Mac 关机时**（在家、周末、商场购物）。因&#x6B64;**「手机直写 iCloud」才是主记录通道**，网页版/Tailscale/对话录入只是 Mac 醒着时的即时补充（原 v0.6 把网页版当主通道是设计倒置，已修正）。
- **核心痛点**：
  1. 在家/出门无法用手机快速记"买了/丢了/卖了"；
  2. 妈妈经常重复买（酱油、大米家里有一堆还买）——全家没有随时能查"家里有啥/在哪"的地方；
  3. 买完东西想拍照**自动识别是什么**，确认后入库，照片带进记录；
  4. 洁梅明确：家庭数据不放心放 GitHub，必须留在自己的 iCloud / Obsidian；Mac 非工作日关机、不愿 pmset 自启，但愿装 Tailscale。

## 二、总体架构（有后端）

### 2.1 一句话机制

**主记录通道（Mac 关机也能用）**：洁梅（苹果）手机用 **Apple 快捷指令「家庭库存·记一笔」** 直接把新物品写进 **iCloud `家庭库存/inbox.jsonl`**（待入库清单，不依赖 Mac）。**Mac 醒来时**本地服务自动把 inbox 合并进 `Obsidian Vault/物品库/items.json`、归位照片、刷新只读快照与飞书/腾讯文档清单。Mac awake 时额外支持网页版（公司 WiFi / Tailscale）与对话录入即时写库。拍照识别由 Mac 服务端持智谱 Key 完成（Key 绝不进浏览器/仓库）。**家人（爷爷/奶奶等长辈，非苹果手机）只查不写**：通过 Mac 醒来同步的**飞书/腾讯文档只读清单**查"家里有啥"，不依赖 iCloud 文件、不装快捷指令。出行打包由规则引擎 + 天气 API 生成清单；旅行结束反馈沉淀为学习库自动优化。

### 2.2 架构图

```
洁梅苹果手机 快捷指令「记一笔」 ──Mac关机也能写──▶ iCloud 家庭库存/inbox.jsonl（待入库,零依赖）
洁梅手机浏览器 浏览/搜索/录入/拍照 ──Mac awake: 公司WiFi 或 Tailscale──▶ 洁梅公司 Mac 本地服务
洁梅 WorkBuddy 对话 ──Mac awake 时──▶ 洁梅公司 Mac 本地服务
Mac 本地服务 ──读写──▶ Obsidian Vault/物品库/（iCloud 2TB 私有同步）
Mac 本地服务 ──服务端持 Key 调──▶ 智谱视觉 API
Mac 本地服务 ──唤醒后合并──▶ inbox.jsonl
Obsidian 物品库 ──洁梅看/链接──▶ 洁梅
Mac 本地服务 ──每次改动自动生成──▶ iCloud 家庭库存/snapshot.html（洁梅苹果手机查）
Mac 本地服务 ──Mac 醒来同步──▶ 飞书/腾讯文档 只读清单（家人安卓查,低敏无Key）
家人 安卓手机 ──浏览器/App 查──▶ 飞书/腾讯文档 只读清单
```

### 2.3 存储架构（5 类落点）

1. **数据主库（私有，已在 iCloud）**：`Obsidian Vault/物品库/`，含 `items.json` / `trips.json` / `packing-rules.json` / `learn.json` / `disposals.json` / `wishlist.json` + `assets/`（照片）。随 iCloud 在洁梅设备间私有同步，**全家数据不进任何 GitHub 仓库、不经任何公网**。
2. **待入库清单（离线写入，零依赖 Mac）**：`iCloud Drive/家庭库存/inbox.jsonl` + `inbox_assets/`。洁梅手机快捷指令直接追加写入，Mac 关机时也能落盘，绝不失记录。
3. **Mac 本地服务（核心，Node）**，职责：
   - 托管前端（HTML/JS），家人手机浏览器打开即用（Mac awake 时）；
   - 读写 `物品库/` 下的 JSON 与照片（数据留在本地 iCloud，绝不外发）；
   - **持有智谱 Key 在服务端**：拍照识别时前端把压缩图发给本机服务，服务调智谱返回字段，Key 只在 Mac 本地 `.env`；
   - **inbox 合并**：服务启动 + 运行期定时检查 `inbox.jsonl`，将待入库项合并进 `items.json`（赋 id、status=在册、source=手机离线）、照片移入 `物品库/assets/`、去重、随后**重生成快照并清空 inbox**；
   - 每次写操作成功后自动重生成 `snapshot.html`；
   - 多人并发按 item id 合并（updatedAt 新者胜）。
4. **洁梅/家人写入（两条通道）**：
   - **主通道 · 手机快捷指令（Mac 关机也能用）**：打开「家庭库存·记一笔」→ 填名称/大类/数量/位置/归属、拍照 → 提交即写入 iCloud `inbox.jsonl`。无需 Mac 开机、无需网络到公司。
   - **补充通道 · 网页版（仅 Mac awake）**：在公司同一 WiFi 用 `http://<Mac名>.local:8787`；不在公司（在家 WiFi / 4G）用 **Tailscale** `http://<mac>.ts.net:8787`。在家 WiFi 与 4G 对手机等价，都需 Tailscale，无需公网 IP/端口映射。
   - **补充通道 · 对话录入（仅 Mac awake，洁梅用）**：WorkBuddy 里说"买了XX/卖了XX"，雪花（同在 Mac）直接改 `items.json` 并触发快照重生。
5. **家人跨平台只读清单（Mac 关机时的兜底）**：Mac 本地服务每次写库后，自动把 `items.json` 生成一份**只读清单（默认飞书多维表，可切腾讯文档）**，只含低敏字段（名称/归属/数量/位置/状态），**不含任何 Key、不含照片原文件**。家人在安卓上用飞书/腾讯文档 App 或浏览器即可随时搜"酱油"。同步时机：Mac 醒来时自动同步；休眠期间看到上次同步版本（隔夜更新，足够防重复买）。

### 2.4 前端形态（与 demo 对齐）

- **单页 Web 应用**，由 Mac 本地 Node 服务托管（`closet/server/` 起服务，`closet/client/` 放前端）。
- **视觉规范 = 已做的 demo（Codex 风格）**：手机壳居中容器（430px、桌面灰底衬托）、大圆角卡片（18–23px）+ 柔和大阴影 `0 14px 38px rgba(26,35,68,.07)`、渐变 hero 卡 + 右上装饰圆环、30px 大标题/750 字重/负字距、柔和蓝主色 `#4967f2`、emoji 做图标 + 彩色圆底、胶囊 chips 筛选、底部 5 tab（中间凸起 ＋ 按钮）、生活化文案。
- **demo 是前端原型**：已实现的交互逻辑（归属锁定、衣物二级字段、家当自由增删、草稿防重置、拍订单/拍包装流程）即为正式开发的前端规范，后端需 100% 支撑这些 UX。

## 四、功能需求（逐页 + 后端）

### 4.1 首页

- **统计面板**：各品类（衣物/鞋/配饰/包/护肤美妆/电子/日用/食品…）件数，点一下即筛选进入列表。
- **天气/穿搭占位**：拉目的地/城市天气（Open-Meteo 免费免 Key），给出"今天适合穿什么"的轻提示（demo 为占位），后期再实现，先
- **需留意**：① 重复购买风险（库内已有同名/近似名）；② 临期（食品类 expiry 近）；③ 用完（护理/消耗品 quantity=0）。点击跳对应列表。
- **前端原型已实现**：demo 首页已含天气+穿搭占位+需留意卡片结构（无快捷操作 section，按洁梅反馈已去除）。

### 4.2 私物（洁梅 / 铄铄 / 爷爷 / 奶奶）

- **归属切换**：顶部切换 我(洁梅)/儿子(铄铄)/奶奶/爷爷（demo 用「我/儿子/奶奶/爷爷」，正式名对齐 v0.8 的 洁梅/铄铄/爷爷/奶奶）。
- **一级分类 chip（demo 已落地的锁定规则）**：
  - 固定三项且**不可删**：`全部`、`衣物`、`护理`；
  - 其余（家电/装备/用户自建）按加入时间 `addedAt` 升序排在固定三项之后，带 `×` 可删；
  - 删除有引用时，其下物品归入自动补建的「其他」分类（避免数据丢失）；
  - `全部`/衣物/护理 拒绝删除（toast 提示）。
- **衣物二级字段（demo 已落地，✅ 已拍板采纳进正式模型，2026-08-27）**：大类=衣物时，可选 **季节 3 档（春秋/夏/冬）** + **款式 3 选（上装/下装/裙装）**；非衣物大类时隐藏这两块。正式 `items.json` 的衣物项用 `season`(春秋/夏/冬) + `subtype`(上装/下装/裙装) 取代 v0.8 的「春/夏/秋/冬/四季多选 + 小类」。
- **护理品用完消失（demo 已落地）**：所有瓶 `sealed=0 && in_use=0` → 整张卡片不渲染（耐用品如冲锋衣 status=active 一直显示，不受影响）。
- **列表/搜索**：默认统计面板 + 按 品类→季节→上装/下装 三级浏览；支持 owner/季节/部位筛选 + 实时搜索；搜"酱油"显示"家里有 3 瓶，在厨房左柜，别买"。卡片显示 名称＋归属＋数量＋状态＋缩略图。
- **重复购买提醒**：录入新物品时，若库内已有同名/近似名（含家庭公用），弹"家里已有 N 件，是否仍录入？"。

### 4.3 家当（家庭公用）

- **定位**：owner=家庭公用（酱油大米等共有消耗品）。
- **大类自由管理（demo 已落地）**：每个具体 chip 末尾 `×` 可删；行尾 `＋ 新分类` 可建；删除有引用时物品归入「其他」（自动补该分类）。
- **＋ 按钮真能加（demo 已修）**：家当页右上 `＋` 调 `goAdd('manual','family')`，进入手动添加页且**归属锁定「家当 🔒」**，不是只弹 toast。

### 4.4 添加（手动 / 拍订单 / 拍包装）

- **手动添加 6 字段（demo 已落地）**：物品名称、品牌、所有人（我/儿子/奶奶/爷爷/家当，按归属联动大类）、大类（联动）、数量、存放位置。衣物自动带季节/款式。可以拍照记录物品式样，这里拍的照片需要AI抠图，只保留物品照片，去掉背景。
- **草稿防重置（demo 已修的真实 bug）**：引入 `_formDraft` 草稿，字段 onchange/oninput 同步到草稿；render 时优先读草稿；切分类/季节/款式改成"就地改 DOM"不再调 render。**根因**：原 `onItemCatChange/setSeasonField/setSubtypeField` 调 `render()` 重建 select，manual 模式用 `bigCats[0]`（永远是衣物）导致选用值被重置，saveItem 永远读到「我+衣物」。
- **拍订单（demo 已实现流程）**：上传订单截图 → 识别 店铺/订单号/日期/金额/规格/保质期，都可以修改 → 确认入库。
- **拍包装（demo 已实现流程）**：上传包装图 → 识别 品牌/名称/规格，都可以修改 → 确认入库。
- **拍照识别后端（v0.8 模块2）**：前端压缩（canvas ≤1000px、JPEG 0.7）传本机服务；服务端智谱识图返回 `{name, category, brand, quantity, tags}`；确认后写入 `物品库/assets/<id>.jpg` 并触发快照重生。Key 仅服务端 `.env`。

### 4.5 出行打包引擎（v0.8 模块3，demo 未做）

- **输入**：目的地、起止日期、活动类型(多选)、出行人(可勾 洁梅/铄铄/爷爷/奶奶/家庭公用)。
- **季节推导**：起始月 → 春(3-5)/夏(6-8)/秋(9-11)/冬(12-2)；跨季取覆盖季。
- **天气接入**：默认 Open-Meteo（免费免 Key）按目的地拉预报；有雨→加雨具；均温<10℃→保暖档；>30℃→防晒档；温差≥12℃→layering。预留和风天气接口（需 Key）。
- **规则** `packing-rules.json`：维度 = 季节 × 活动 × 大类 → 推荐模板(含 tags)。
- **匹配**：用模板去 `items.json` 找「在册」且匹配 owner/标签的物品，标「你已有 ✓ / 需要准备 ⚠️」；消耗品按 quantity 提示是否够。
- **双通道**：① 网页版「出行打包」tab；② 对话里说"帮我打包"由「物品库打包助手」skill 生成 richer 建议（共用同一规则文件）。

### 4.6 旅行后反馈 + 学习闭环（v0.8 模块4，无前端表单）

- **入口**：洁梅在对话里告诉雪花"XX 好用/没用上、漏了YY、要补ZZ"；**不做一个前端逐条勾选页面**（前端只管记录与查看，复盘在对话里聊更顺）。
- **学习沉淀** `learn.json`：同类「没用上」≥2 次→下次打包默认不勾；遗漏/补充确认→写入该(季节×活动)模板。
- **效果**：同类型出行第二次起更准；可随时问"下次去XX带什么"。

## 六、家人只读（v0.8 模块0/1，已拍板）

- 家人（爷爷/奶奶等长辈、安卓手机）**只查不写**：打开同一物品库界面即为只读模式（无写入按钮）；Mac 关机时走飞书/腾讯文档只读清单兜底。
- 原因：Apple 快捷指令是苹果专属，家人用安卓装不了、也难直接开 iCloud 文件；Mac 关机时网页版不可达。故家人不写、只查。
- 安全：只读清单是低敏库存，无 Key、无全家数据全量、无照片，符合洁梅"不放心公网"底线。

## 七、拍照识别 / AI（v0.8 模块2）

- 流程：点「＋」→ 调起相机/选图 → 前端压缩（canvas ≤1000px、JPEG 0.7，单图 ~150KB）→ 传本机 Mac 服务 → 服务端智谱识别 → 返回建议字段 → 前端展示让洁梅/家人确认或修正 → 保存即 status=在册，照片写 `物品库/assets/<id>.jpg`，触发快照重生。
- **Key 安全**：智谱 Key 只存在于 Mac 服务端 `closet/server/.env`，不进前端、不进任何仓库、不进 Obsidian 数据文件。
- 无照片也可：极简表单（owner 默认洁梅、名称、大类、数量、位置、拍照可选）→ 两步内完成。
- 丢/卖/用完：卡片「⋯」→ 标记 → 写 `disposals.json`（date＋原因），status 变更，**不删除数据**；触发快照重生。

## 九、唯一新增 / 变更核心逻辑（阈值与样例）

1. **主记录通道 = 手机快捷指令 → iCloud inbox（零依赖 Mac）**；网页版/对话录入为 Mac awake 时的即时补充。
2. **inbox 合并规则**：服务启动 + 每 N 分钟（如 5 分钟）检查 `inbox.jsonl`；每条 → 赋 id、status=在册、source=手机离线；按名称归一化（去空格/括号）与 `items.json` 比对：命中则并入数量或跳过并留痕；照片移 `物品库/assets/`；合并后重生成 `snapshot.html` 并清空 inbox。
3. **零丢失**：inbox 写入即落 iCloud，Mac 未醒也不丢；仅"进主库+快照刷新"延到 Mac 下次醒来。
4. **全家 owner 模型**：owner ∈ {洁梅,铄铄,爷爷,奶奶,家庭公用}；洁梅可搜可写，家人打开同一界面即只读（无写入按钮），另保留飞书/腾讯文档只读清单作 Mac 关机兜底。
5. **重复购买拦截**：录入（含 inbox 合并时）按名称归一化模糊匹配，命中 → 弹确认/合并。
6. **拍照识别返回字段映射**：智谱输出 → {name, category, brand, quantity, tags}，确认后写入。
7. **照片压缩**：canvas ≤1000px、JPEG q0.7，单图 ~150KB。
8. **快照生成**：每次成功写 `items.json`（含 inbox 合并后）重生成 `iCloud Drive/家庭库存/snapshot.html`（内联全部数据，纯前端可搜，无服务器依赖）。
9. **多人合并**：按 item.id 合并，updatedAt 新者胜。
10. **Key 隔离**：智谱 Key 仅 Mac 服务端 `.env`，前端只收"识别结果"。
11. **Mac 休眠行为**：不 pmset 自启、不强制常开；休眠期间网页版/对话不可用，但快捷指令仍可写 inbox；全家走 iCloud 快照。
12. **前端归属锁定（demo 验证）**：私物页 衣物/护理/全部 不可删；家当 + 锁定归属家当；手动添加草稿防重置。
13. **衣物二级分类（✅ 已拍板采纳，2026-08-27）**：季节 3 档（春秋/夏/冬）+ 款式 3 选（上装/下装/裙装），正式 `items.json` 模型采用。
14. **消耗品用完消失（demo 验证）**：护理/消耗品所有瓶 finished → 列表不渲染。

## 十一、验收标准

### A. 后端 / 架构（v0.8 原 12 条）

1. Mac 关机状态下，洁梅用手机快捷指令「记一笔」提交一条物品 → `iCloud 家庭库存/inbox.jsonl` 立即出现该记录（零依赖 Mac，记录不丢）。
2. 上述记录待 Mac 醒来 → 服务自动合并进 `items.json`、`snapshot.html` 刷新、inbox 清空；家人随后在清单里能看到该物品。
3. 在公司同一 WiFi / Tailscale 下，家人手机浏览器打开应用，能看到"我有哪些东西"（列表+搜索），两步内新增一条在册物品（可带照片）。

5. 搜"酱油"显示家庭公用库存数量与位置，录入同名物品弹重复提醒。
6. 物品可标记丢失/已售/用完，状态正确且历史留痕；数据只在 `Obsidian Vault/物品库/`（已确认 iCloud），无 GitHub 副本。
7. 输入「冬天+爬山+某地(有雨)」生成清单，标已有/需准备，天气把雨衣加进。
8. 出行结束 App+飞书触发反馈；填后 `learn.json` 产生增减，第二次同类更准。
9. 全家多手机读写不互相覆盖（按 id 合并）。
10. Mac 关机/休眠状态下，家人用安卓手机打开飞书/腾讯文档只读清单能搜到"酱油 3 瓶 厨房左柜"（跨平台兜底验证；安卓不依赖 iCloud 文件）。
11. 现有 299 件 Excel 迁移数据 + 8 条心愿可用；周末雷达线上功能/数据/缓存与改动前一致（本工具不碰它）。
12. 数据主库仅在 iCloud/Obsidian，全家数据不进 GitHub、不经公网。
