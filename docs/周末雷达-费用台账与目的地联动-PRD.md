## 二、实现思路（一句话机制）

- **费用**：把"按天分散的多笔明细"改成"按天一行的大类金额"——新增 `route.dayCosts` 数组，每个元素对应一天（`day:0` 为全程），内置 `transport/stay/ticket/food/other` 五个金额格，每个格自带 `amount` 与 `type`（固定/预估）。日卡里的费用区块退化为**只读展示**（从 `dayCosts` 读取当天），所有录入/修改都在台账表格里做。
- **汇总**：`costSummary()` 从"拼文本+复制"改成"渲染 HTML 面板+弹窗"。
- **联动**：抽一个公共函数 `addToRoutePlan(destName, opts)`，三个模块的卡片按钮都调它，弹同一个表单；**档位由天数自动计算**，不再让用户选。

## 三、改动一：费用台账（按天一行 · 参考飞书表）

### 3.1 入口

路线卡片头部现有的「全程花费预计」条右侧，新增按钮 **「📒 费用台账」**（不进编辑模式也能点）。

### 3.2 台账界面（全屏弹窗，宽度 min(1000px, 94vw)）

顶部固定条：
```
📒 成都-卧龙-四姑娘山 · 费用台账          固定 ¥12,400 · 预估 ¥5,800 · 合计 ¥18,200 · 人均 ¥3,640（5人）
[👨‍👩‍👧 人数：5]                                    [✕ 关闭]
```

表格（可横向滚动，手机端保持表格形态）：

| 日期 | 交通 | 住宿 | 门票 | 吃饭 | 其他 | 当日合计 | 备注 |
|---|---|---|---|---|---|---|---|
| 全程 | 8800 固定 | 0 | 0 | 0 | 0 | ¥8,800 | 往返高铁+租车 |
| Day1 | 0 | 780 固定 | 0 | 200 预估 | 0 | ¥980 | |
| Day2 | 120 固定 | 520 固定 | 450 固定 | 400 预估 | 0 | ¥1,490 | 熊猫基地 |
| Day3 | 0 | 880 预估 | 760 固定 | 280 预估 | 0 | ¥1,920 | 双桥沟 |

字段规则：
- **日期**：第一列固定为 `全程` + `Day1…DayN`（N = 该行程天数），一行一天，不能增删。`全程` 用于高铁、租车、保险这类不属于某一天的。
- **五大类金额格**：
  - **交通** = 高铁票 + 租车费 + 油费 + 停车费
  - **住宿**
  - **门票** = 景区门票 / 乐园
  - **吃饭**
  - **其他**
- **金额**：每个格子填一个数字，输入即时更新顶部合计与当日合计。
- **类型**：每个金额格下方有一个 `固定 / 预估` 小按钮，点一下切换（固定=绿底，预估=橙底）。
- **备注**：每行一个备注格，写当天备注或某项说明。
- **当日合计**：自动计算该行五大类之和。
- **底部合计行**：自动计算每一列的总计，再汇总成固定/预估/合计。

行为：
- 打开台账即看到整趟所有天，**一眼看清每天花多少**。
- 输入金额即时更新：顶部合计、当日合计、底部合计行、路线卡片的「全程花费」条。
- 不支持的：不再做"一行一笔明细"、不再做"从飞书表格粘贴导入"（洁梅反馈要简化成按天记）。

### 3.3 数据结构与迁移

新增（写进 `data/routes.json` 的每条路线）：
```json
"dayCosts": [
  {"day":0, "transport":{"a":8800,"t":"fixed"}, "stay":{"a":0,"t":"fixed"}, "ticket":{"a":0,"t":"fixed"}, "food":{"a":0,"t":"fixed"}, "other":{"a":0,"t":"fixed"}, "note":"往返高铁+租车"},
  {"day":1, "transport":{"a":0,"t":"fixed"}, "stay":{"a":780,"t":"fixed"}, "ticket":{"a":0,"t":"fixed"}, "food":{"a":200,"t":"est"}, "other":{"a":0,"t":"fixed"}, "note":""}
]
```
- `day`：0 = 全程，1..N = 第几天。
- 每个大类字段：`a` = amount，`t` = type（`fixed` | `est`）。
- **兼容迁移**：首次打开台账时若 `route.dayCosts` 不存在，自动把老的 `daily[i].costs.items` 按分类汇总进 `dayCosts`（交通类合并到 `transport`，住宿→`stay`，门票→`ticket`，吃饭→`food`，其他→`other`），迁移后老字段不再写入、只保留不删（防回滚丢数据）。
- 如果同时存在老 `route.ledger`，也按同样规则汇入 `dayCosts`，汇入后清空 `ledger`。
- 日卡费用区块改为**只读**：从 `dayCosts` 读取当天，显示"当日 固定/预估/合计"；区块底部一行小字链接「在费用台账里改 →」。

### 3.4 人均

行程头部与台账顶部显示人均，默认按 **5 人**（洁梅、先生、2 位老人、铄铄）。台账顶部可点数字改人数，存在 `route.pax`（默认 5）。

## 五、改动三：三模块 → 一键加进路线规划

### 5.1 按钮落点

| 模块 | 卡片现有按钮 | 新增 |
|---|---|---|
| 🔥 本周最热 | ⭐收心愿 / 👎没兴趣 / ✅去过了 | **🗺️ 加进路线** |
| 🗓️ 下一个假期（候选地） | ✅确认去这里 / ⭐收心愿 / 👎 / ✅ | **🗺️ 加进路线**（与"确认去这里"并存：确认=定这次假期，加进路线=先存一条规划） |
| ⭐ 心愿单 | 调想去程度 / 编辑备注 / 标记已去过 / 删除 | **🗺️ 加进路线** |

去重：若路线库已有同名（去掉"（规划中）"后缀比对）路线 → 按钮变 `🗺️ 已在路线库`，点击跳到路线 tab 并把该卡片展开 + 高亮 1.5 秒。

### 5.2 弹出表单（统一）

```
🗺️ 加进路线规划
目的地：[惠州·双月湾          ]   ← 预填，可改
出行日期：[            ] 空着就是"待定"
天数：[2]                       ← 只填这个
档位：1-2天                     ← 根据天数自动算，只读展示
状态：(•) 规划中  ( ) 已走过
[ ] 同时收进心愿单                ← 来源是心愿单时不显示
                      [取消] [✅ 生成路线]
```

档位计算规则：
- 1–2 天 → `1-2天`
- 3–4 天 → `3-4天`
- 5–7 天 → `5-7天`
- ≥8 天 → `8天+`
- 天数输入框 oninput 时实时更新档位 pill

生成后：
- 建一条 `{id:'r-user-…', source:'user', status, daily: genPlan(name, days)（沿用现有每日行程卡）, dayCosts: [全程 + Day1…DayN 空行], pax:5}` 插到路线库最前。老路线的 `daily[i].costs` 字段保留不删，数据迁移时再归并进 `dayCosts`。
- 若来源是心愿单 → 该心愿状态自动置为 `已安排(scheduled)`。
- 自动切到「🗺️ 旅行路线」tab 并展开新路线，toast：`✅ 已加进路线规划，点「✏️ 编辑模式」排每天行程，点「📒 费用台账」记账`。

### 5.3 路线库顶部加筛选

`[全部] [🧭 规划中] [✅ 已走过]` 三个 chip，默认全部。对应洁梅"路线库 = 走过的 + 规划中的"定位。

## 七、验收标准

1. 点「📊 花费汇总」弹出账本面板，**不再出现"已复制"toast**；面板能看到每趟合计、人均、分类占比、可展开每日明细。
2. 打开任意路线点「📒 费用台账」，出现整趟一张按天表格（全程 + Day1…DayN 每一行一天，列是交通/住宿/门票/吃饭/其他/备注）；在某天的格子填数字，顶部合计、当日合计、路线卡片"全程花费"条实时更新。
3. 在金额格下方点「固定/预估」按钮可切换该格类型，顶部"固定 vs 预估"随之变化；台账顶部可点人数改 pax，人均同步变。
4. 老数据（成都行程里已按天录的费用）打开台账后自动出现在表格里，金额合计与改造前一致。
5. 在本周最热任一卡片点「🗺️ 加进路线」→ 填天数 → 生成路线 → 自动跳到路线 tab 并看到新路线；再回本周最热，该卡片按钮变「已在路线库」。
6. 心愿单卡片加进路线后，该心愿状态变为"已安排"。
7. 路线库顶部筛选 chip 能正确过滤规划中 / 已走过。
8. 全部改动通过 jsdom 烟雾测试：零运行时报错，所有新按钮可点。
