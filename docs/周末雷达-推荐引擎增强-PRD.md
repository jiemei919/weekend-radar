## 三、改动设计（唯一新增/变更逻辑）

### 3.1 新增「🏨 度假酒店」常驻推荐通道
- **新增真值源** `data/resorts.json` + 前端 `app/resorts.js`：度假酒店/乐园酒店库。每条字段：
  `name / city / 核心活动[儿童乐园,温泉,徒步,泳池,动物园…] / 适合人群[老人,小孩,大人] / 价格区间 / 来源(已去过revisit / 未去过新搜) / trigger(价优?)`。
- **来源三类**：
  ① 已去过且适合"酒店度假"的（新兴禅泉/巴伐利亚/南昆山/三正半山/龙门竹溪山境 等，转成"酒店复访"卡）；
  ② 没去过的优质度假酒店（清远长隆已进候选池；新增如省内长隆类/温泉度假村）；
  ③ 雪花按档位新搜罗。
- **卡片形态**：新增「🏨 度假酒店」卡（区别于目的地卡），突出"酒店即目的地 + 活动清单 + 适合谁 + 价优与否"。
- **展示位**：本周最热 与 下一个假期 均可出现（尤其 1-2 天档 / 省内）。

### 3.2 运动类可复推（去过也能推）
- 在 visited 库给运动/活动类打 `activityTag`（从化→桨板、古龙峡→漂流、连州地下河→溶洞；已有部分 revisit 带 activity）。
- `applyVisitFilter` 增加**运动豁免分支**：若 exclude 项带 `activityTag` 且当前月份/天气落在 `season/weather` 窗口 → 放行并标 **【运动·可复玩】**，不当成"新目的地"硬推，而是"天气好了去玩一下"。

### 3.3 酒店价优触发
- 度假酒店/目的地加 `trigger:"价优"` + `priceNormal` / `priceNow`（雪花填或标"待核"）。
- 价优核查：检索该地近期促销（长隆大促、温泉淡季、奥莱换季）。命中且确实低于平日 → 推并标 **【价优·比平日低 X%】**；否则不推。

### 3.4 避雷过滤（公开口碑）
- 候选生成增加**避雷核查**步：对候选项检索小红书/马蜂窝/携程差评与避雷帖，聚合"避雷关键词 + 量级"。命中且量级大（评分<4.0 或差评集中"坑/雷/别去"）→ 拦截或降权，标 **【避雷·N 人反馈】**。
- 与 visited 的 `block`（洁梅个人避雷：海鸥岛/七星岩等）互补：个人避雷是硬规则，公开避雷是额外保险，避免推"大众都说雷"的地方。
- 数据源：`data/avoid.json`（雪花维护的公开避雷聚合）或每次搜罗时实时检索。

### 3.5 已去过库"读全表"兜底
- 对"赣州"这类未单列入库的地名，采用"区域 + 已知子景点"兜底（赣州→南武当/三百山 等子景点命中即拦），避免漏推式漏拦。
- 后续任何新推荐先过 visited 库，命中 block/exclude 不推为目的地（运动豁免/酒店复访除外，且必须明确标注）。
