# 「周末雷达」需求文档 v0.5（交互重构版）

> 给洁梅的旅行规划雷达 | 撰写：雪花 ❄️ | 2026-07-28 | 状态：demo + PRD 确认中，**确认前不动代码**

## 0. 一句话定位（相对 v0.4 的变化）

v0.4 把项目升级为"全家旅行规划雷达"，但**界面把「法定节假日、周末、日常推荐」混在一个页面，tab 也过多**。本版做交互重构：
- **法定节假日与周末分开规划**
- **顶部保留 4 个主 tab**：本周最热、下一个假期、⭐ 心愿单、旅行路线（新增「⭐ 心愿单」长期心愿池，见 1.3）
- **去掉页面级 tab**：去过点评、我的口味、设置功能仍保留在后台数据层，不再作为顶部导航
- **新增「下一个假期」模块**：点击触发后，雪花每天按「出发天数 + 当月季节 + 最佳时间 + 安全」推荐目的地，直到洁梅确认目的地；确认后自动切换到「旅行路线」模块，推荐具体路线（按收藏>点赞>浏览权重），并可联动 iPhone 日历提醒。

## 1. 界面结构（唯一新增/变更逻辑）

### 1.1 顶部导航（3 tab）

| tab | 定位 | 内容 |
|---|---|---|
| 🔥 本周最热 | 日常周更推荐 | 按当前周更周期（周一 07:30 更新）罗列 5-8 个目的地 + 1 个铄铄彩蛋位；可反馈、换一批 |
| 🗓️ 下一个假期 | 节假日专项推荐 | 显示下一个法定节假日；一键触发「帮我找目的地」；触发后到确认前，每天推送新目的地；含「确认去这里」入口 |

| 🗺️ 旅行路线 | 路线库：走过的 + 规划中的 | 记录洁梅<b>所有走过的路线</b>与<b>规划中的路线</b>（多条并存）；每条含完整 Day-by-Day 行程 + 候选路线参考；规划中路线可一键加入 iPhone 日历 |

### 1.2 去掉的页面级 tab

- ✅ 去过·点评、🧬 我的口味、⚙️ 设置 **不再出现在顶部导航**
- 功能不删除：
  - 去过点评 / 我的口味 / 设置数据仍保留在 `data/` 与本地存储中
  - 雪花在对话中可读取并更新这些数据
  - 后续如需查看，可通过「我的」侧边入口或对话指令调出（v0.5 先不实现页面，只保留数据能力）

## 1.3 「⭐ 心愿单」tab（本版新增）

### 1.3.1 定位
长期想去的目的地池，**跨假期保存**，与以下两者区分：
- 「🔥 本周最热」：当期推送，时效性强
- 「🗓️ 下一个假期 · 确认去这里」：本次假期真要去的，会进入路线规划
- 「⭐ 心愿单」：**洁梅长期想去、想攒着以后去的地方**，可来自雪花推荐，也可来自洁梅自提

### 1.3.2 页面内容
- 顶部一句说明：跨假期保存、规划时优先匹配
- 心愿卡片列表，每张含：
  - 目的地名 + emoji
  - 想去程度：🔥 强 / 🌤 中 / 🌫 弱（可循环切换）
  - 适合档位标签：1-2 天 / 3-4 天 / 5-7 天 / 8 天+
  - 来源（雪花推荐 / 洁梅自提）+ 添加日期
  - 备注（洁梅自写，如"等铄铄大一点""暑假人多避开"）
  - 状态：想去中 / 已安排（关联某假期）/ 已去过（可打星）
  - 操作：调想去程度、编辑备注、**标记已去过 / ↩️ 改回想去（可逆）**、删除
  - **状态可逆（本版新增）**：「已去过」不是终态——点击可一键「改回想去」，status 由 `done` 退回 `want`，该心愿不丢失，方便以后再去
- 空态引导：本周最热 / 下一个假期卡片点「⭐ 收心愿」，或对话里说"我想去 XX"

### 1.3.3 来源与联动（唯一新增逻辑）
- 本周最热卡片「⭐ 收心愿」→ 加入心愿单（status=想去中）
- 下一个假期候选卡片「⭐ 收心愿」→ 加入心愿单（不触发确认，即"先记着，这次不去"）
- 对话里洁梅说"我想去 XX" → 雪花直接写入心愿单
- 「下一个假期」搜罗时，雪花**优先匹配**心愿单中"适合当前档位 + 状态=想去中"的目的地，先推这些，再补新搜的
- 心愿单某条被「确认去这里」→ status 改为已安排；某条「已去过」→ status 改为已去过（雪花在对话中按反馈更新）
- **状态可逆**：已去过的心愿可一键「改回想去」（status 由 done 退回 want），不丢失该心愿，方便之后再去

### 1.3.4 数据模型（写入 `data/wishlist.json`）

每条心愿：
```json
{
  "id": 201,
  "name": "四川 · 成都看大熊猫 + 三星堆",
  "emoji": "🐼",
  "level": "强",
  "tier": "5-7天",
  "source": "洁梅自提",
  "addedAt": "2026-07-31",
  "note": "想看大熊猫胜地，顺带三星堆",
  "status": "want"
}
```
- status 取值：want（想去中）/ scheduled（已安排）/ done（已去过）
- doneRating（已去过时可选打星，0-5）

## 3. 「下一个假期」tab（本版核心新增）

### 3.1 顶部信息区（轻量）
- 显示：下一个法定节假日名称、日期区间、天数
- 显示：基于该假期默认天数的推荐档位（如"中秋 3 天 → 3-4 天档 · 广东+邻省"）
- 显示：洁梅已告知的请假片段（如有），以及拼假后的连续可用天数
- 一个主按钮：**「🚀 帮我找目的地」**

### 3.2 触发「帮我找目的地」（唯一新增核心逻辑）

**触发条件**：洁梅点击按钮，或在对话中说"帮我找目的地"等同类指令。

**触发后行为**：
1. 雪花进入「目的地推荐模式」，每天给洁梅推荐 1-3 个候选目的地
2. 推荐渠道：小红书 / 携程 / 马蜂窝 / 去哪儿 / 抖音近 14 天高热内容
3. 推荐依据（按优先级）：
   - **出发天数**：读取 `holidays.json` + `leaves.json` 计算连续可用天数，按 1-2天/3-4天/5-7天/8天+ 四档选范围
   - **当月 / 季节**：当前月份 + 目的地最佳旅行季节匹配（如 9 月优先秋景、海岛避开台风季）
   - **最佳时间**：目的地当月是否处于景色/活动/花期/观兽最佳窗口
   - **安全问题**：台风、暴雨、地质灾害、高海拔风险、景区关闭等；存在明确安全风险的直接过滤或加⚠️强提示
4. 每条推荐包含：目的地名称、类型标签、番禺出发交通方式与时长、一句话推荐理由、最佳时间说明、安全提示、来源平台/热度、亲子适配等级
5. **持续推荐**：直到洁梅点击「✅ 确认去这里」或对话中明确确认某个目的地；确认后立即停止新目的地推荐

### 3.3 确认目的地（唯一新增核心逻辑）

- 每个候选卡片上有按钮：**「✅ 确认去这里」**
- 点击后弹出二次确认："确定选择 XX 作为本次假期目的地？确认后停止推荐新目的地，进入路线规划。"
- 确认后：
  - 该目的地写入 `data/confirmed-trip.json`
  - 顶部 tab 自动切换到「🗺️ 旅行路线」
  - 雪花开始为该目的地生成**完整行程计划**（见第 4 章），并写入 `data/plan.json`

### 3.4 数据文件

- `data/confirmed-trip.json`：记录当前确认目的地（destination / dateRange / days / confirmedAt / status）
- `data/holidays.json`、`data/leaves.json`：沿用 v0.4

## 4. 「旅行路线」tab（本版核心新增）

### 4.1 定位：路线库（多条，含历史存档）

「🗺️ 旅行路线」不再是单条确认行程，而是洁梅的**路线库**，以列表形式展示，**多条路线并存，互不影响**：

- **✅ 已走过**：洁梅实际出行过的路线，雪花逐条记录存档
  - 来源：洁梅在对话里说"XX 那趟路线记一下"，或雪花读取洁梅飞书手工计划表（见 4.7）导入
  - 已走过的路线展示完整 Day-by-Day 行程，作为历史参考；日历导出按钮置为"行程已结束"（不再可加入未来日历）
- **🧭 规划中**：洁梅在「下一个假期」确认目的地后，雪花**自动新增一条规划中路线**到库顶，并生成完整 Day-by-Day 行程（见 4.2）
- 点击任意一条路线卡片可**展开/收起**看完整行程；多路线各自独立

### 4.2 雪花生成「完整行程计划」（本版核心，不是单条路线）

确认目的地后，雪花在路线库新增一条「规划中」路线，并**先生成一份完整的 Day-by-Day 行程计划**，对齐洁梅手工习惯（见 4.7 真实样本），而非只给几条零散路线链接。

- 计划以"天"为单位，每天一行
- 每天字段：**日期 / 行程方式（高铁·行车·飞机） / 计划（当天安排，含时间点） / 住宿（酒店名 + 海拔） / 行程时间（行车公里·用时·路线节点） / 费用（可选）**
- 生成依据：
  - 综合「下一个假期」推荐的候选路线（按收藏>点赞>浏览排序）成一份"不赶"的行程，不打卡式
  - 套用全家约束：博物馆 2.5-3h、自然景区×1.2、8 点起 9 点出发、避免盘山国道、高海拔三原则、熊猫/顶级博物馆优先
  - 住宿：中等偏上 / 度假酒店（纯泡温泉玩酒店时）
- 生成后展示在「🗺️ 旅行路线」tab，洁梅可逐天反馈调整（"Day3 太赶了""Day5 想换酒店"），雪花迭代

### 4.3 路线参考（保留，作为生成计划的素材）

- 页面仍展示候选路线卡片（来源平台 + 帖子链接 + 收藏/点赞/浏览 + 适配标签），供洁梅调整计划时参考
- 排序权重：**收藏数 > 点赞数 > 浏览数**（见 4.4）

### 4.4 路线排序权重（唯一新增逻辑）

**排序公式：收藏数 > 点赞数 > 浏览数**

实现方式：
1. 对每条路线提取（收藏数、点赞数、浏览数）
2. 先按收藏数降序；收藏数相同按点赞数降序；再相同按浏览数降序
3. 若没有明确数字，按平台热度标签（如"爆火""热门""小火"）做定性映射后排序

### 4.5 全部加入 iPhone 日历（核心：一次生成整份，每天一个事件）

洁梅的原话：**"做出整个旅行计划以后，比如 7 天的路线计划，我需要把当天的行程、住宿、路线都放到 iPhone 日历里面。"** 因此这不是单条路线、也不是一个总事件，而是**整份行程计划的每一天生成一个独立的 iPhone 日历事件**。

- 点击「📅 全部加入 iPhone 日历」后，**整份行程计划的每一天生成一个日历事件**（8 天 = 8 个事件）
- 每个日历事件内容：
  - **标题**：DayX · 当天主题（如"Day2 · 卧龙熊猫基地"）
  - **日期**：当天日期
  - **时间**：尽量从计划中提取具体时间（如"8点出发""11点进景区""4点半出景区"）；提取不到则设为全天事件
  - **备注/地点**：当天计划全文 + 住宿酒店 + 行车路线 + 关键提醒（如"海拔 3100，老人慢走"）
- 实现：生成**一份合并的 `.ics` 文件**（含所有天的 VEVENT），洁梅点一次即全部导入 iPhone 日历 App
- v0.5 先用 `.ics` 文件方式；后续升级为直接写入 iCloud 日历（需 user 身份授权 calendar scope）

### 4.6 行程计划数据模型（写入 `data/plan.json`）

```json
{
  "destination": "成都-卧龙-四姑娘山-新都桥",
  "dateRange": "2026-09-30 ~ 2026-10-07",
  "days": 8,
  "daily": [
    { "date":"2026-09-30", "mode":"高铁",
      "plan":"下午请假，广州→成都，晚10点到，住成都东站附近；高铁上完成物资采购直送酒店",
      "hotel":"Zsmart智尚酒店(成都东站)", "routeTime":"" },
    { "date":"2026-10-01", "mode":"行车",
      "plan":"8点拿车吃早餐，装车去卧龙，玩熊猫基地，结束直接回酒店休息",
      "hotel":"卧龙文玥民宿(1900)", "routeTime":"10点出发→卧龙1点，约220km" }
  ]
}
```

### 4.7 洁梅手工计划格式参考（真实样本，必读）

- 来源：洁梅飞书表格 `wiki RYtiwPfwXiXlXMkoJz9c5ljlnqg`（2026 国庆 四川 8 天：成都-卧龙-四姑娘山-甲居-新都桥-康定-三星堆）
- 列结构：**日期 / 行程方式 / 计划 / 住宿 / 行程时间 / 行车公里 / 行车费用 / 住宿费 / 吃饭 / 其他**
- 关键特征（雪花生成的计划必须对齐）：
  - 计划列含**详细时间点**："8点出发""11点进双桥沟（5小时）""4点半出景区去猫鼻梁看日落"
  - 住宿列含**具体酒店名 + 海拔**：如"四姑娘山雪山情民宿（3100）""新都桥（3500）"
  - 行程时间列含**行车公里 + 节点时刻**："甲居离新都桥160公里，车程3.5小时"
  - 末两行是**费用汇总**（行车/住宿/吃饭/其他合计 13797.5）与**人均**
- 雪花生成的计划 = 同样的列结构，只是数据由雪花编排

### 4.8 数据文件（本版改为路线库模型）

- **`data/routes.json`：路线库（数组，每条 = 一条路线记录）**，结构：
  ```json
  {
    "id": "r-chengdu-2026",
    "name": "成都-卧龙-四姑娘山-新都桥-康定-三星堆",
    "status": "done",            // done=已走过 / planned=规划中
    "isExample": false,          // 是否示例数据
    "dateRange": "2026-09-30 ~ 2026-10-07",
    "days": 8,
    "tier": "5-7天",
    "daily": [ ... 见 4.6 ... ],
    "candidateRoutes": [ ... 见 4.3 ... ]
  }
  ```
  - 雪花每记录一条走过的路线 / 生成一条规划中路线，就向该数组追加一条
- `data/plan.json`：保留为单条路线计划的独立文件（可选），与 `routes.json` 中某条记录的 `daily` 字段对应；v0.5 优先以 `routes.json.daily` 为准
- `data/confirmed-trip.json`：保留最近一次确认目的地的轻量指针（供定时任务/快捷入口定位），路线完整内容以 `data/routes.json` 为准

## 8.5 技术实现方案（PWA，已确认）

### 8.5.1 选型结论（2026-07-31 洁梅拍板）
采用 **PWA（Progressive Web App）单一网页方案**，一套代码覆盖 **Mac / 微信 / iPhone** 三端。**不注册微信小程序、不做 iOS 原生 app。**

### 8.5.2 三端落地方式
| 端 | 实现方式 | 说明 |
|---|---|---|
| **Mac** | 现有 `周末雷达.app`（本地 HTML 壳）继续用 / 拖进 Dock；PWA 化后支持离线、图标固定 | 零成本，双击即开 |
| **微信** | 直接把网页链接发微信，点开即 H5 **无需注册小程序**即覆盖 90% 场景 | 后期若需固定入口/推送再评估小程序（免费注册但需重写代码+备案审核） |
| **iPhone** | Safari「添加到主屏幕」→ 桌面图标、可全屏、可离线，体验近似原生 App | 免费、即时生效，不付 $99/年开发者费 |

### 8.5.3 实现机制（v0.5 开发时落地，叠加在现有 `app/` 之上）
1. 新增 `app/manifest.webmanifest`：应用名「周末雷达」、图标、启动屏、`display=standalone`（全屏无地址栏）、`theme_color`。
2. 新增 `app/sw.js`（Service Worker）：缓存 `index.html` / `data.js` / `holidays.js` / 图标等静态资源，实现离线可用与秒开；数据更新走「缓存优先 + 后台更新」策略（每周一榜单刷新后仍即时拉取新数据）。
3. 图标资源：准备 192×192 与 512×512 PNG，置于 `app/icons/`（Mac Dock 与 iPhone 主屏幕通用）。
4. **不动现有业务逻辑**：PWA 仅叠加壳层，4 tab 交互、节假日、心愿单、路线库逻辑不变。
5. 部署：本地文件可直接用 `周末雷达.app` 壳打开；如需微信里打开，**需一个可公网访问的 URL**——洁梅无自有域名，**不用买域名**，用免费托管平台的子域名即可（0 元免备案）。**首选 Gitee Pages（*.gitee.io，国内访问稳、微信点开基本能开）**；海外平台（Vercel/Netlify/Cloudflare Pages/GitHub Pages）国内微信访问不稳（需 VPN），不优先；最稳小钱方案为腾讯云静态网站（腾讯系域名微信零拦截，几元/月）。微信直接点开链接通常放行，本工具为静态页无 JS 跨域跳转问题。托管由雪花开发时一键部署。

### 8.5.4 与小程序 / 原生 app 的取舍（备忘）
- **微信小程序**：个人免费注册但需重写代码（微信框架不能复用现有 HTML）+ 备案(3-20 工作日) + 审核；仅当「微信内固定入口 + 推送通知」成为硬需求才上。
- **iOS 原生 app**：Apple Developer $99/年 + 每次上架审核；洁梅一人用不划算，PWA 主屏幕图标体验已近似原生且免费即时。
- **关键**：当前 `app/index.html` 已是网页，PWA 复用同一套代码，几乎不推倒重来。
