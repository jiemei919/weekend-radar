# 周末雷达 · 旅行路线「每日行程卡」新格式 PRD

> 状态：待洁梅确认「可以去开发了」后开工
> 背景：洁梅反馈——当前旅行路线用一张大表把每天挤成一行纯文本，不方便看；希望分天清晰展示：**当天做什么 / 路线什么样 / 住哪里 / 时间怎么排 / 路上注意事项**。

## 1. 问题根因
当前 `app/index.html` 的「🗺️ 旅行路线」tab 用 `routePlanTableHTML()` 把每天渲染成**一张大表里的一行**（日期/方式/计划/住宿/路线 挤在一起）。洁梅要的是**分天的"行程卡"**，信息维度拆开、看得清。

## 2. 实现思路（一句话机制）
给每条 daily 增加**「时间轴 timeline」**和**「注意事项 tips」**两个结构化字段；渲染从"一张大表"改成**「每日行程卡」**（时间轴 + 路线 + 住宿含海拔 + 注意事项），原来的整表折叠保留为"完整表（原始）"详情。

## 3. 各入口 / 落点改动
- **数据模型**：`daily[]` 每条新增 `timeline: [{time, action}]` 与 `tips: string|string[]`。原 `plan/route/hotel` 字段**全部保留**做兜底。
- **已有成都数据**：雪花按原 `plan/route/hotel` 提炼补填 `timeline` 和 `tips`（不丢信息；demo 已用真实数据预览）。
- **渲染**：新增 `dayCardHTML(daily[i])` 渲染每日卡；`routePlanTableHTML()` 改为**折叠**的"完整表（原始）"，默认不展开。
- **「确认去这里」自动生成规划中路线**：`genPlan()` 产出每日卡时，一并生成带 `timeline` 的每天时间轴 + `tips` 注意事项（雪花按目的地生成合理内容）。
- **对话迭代**："Day3 太赶 / Day5 换酒店 / 加个注意事项" 继续支持，改的就是对应 daily 的字段。
- **加入 iPhone 日历 (.ics)**：仍按每天一个事件（已有逻辑不变）。

## 4. 唯一新增 / 变更逻辑（阈值与样例）
- **时间轴字段** `timeline: [{time:"08:00", action:"拿车+早餐，装车出发"}, ...]` —— 雪花从原 `plan` 文本提取/整理关键时间点；展示为竖线圆点时间轴。
- **注意事项字段** `tips` —— 雪花按路线实际风险填（堵车、山路、老人小孩、酒店条件等）。
- **高原自动提示**（复用全家旅行"高海拔三原则"）：渲染时若 `hotel` 含海拔 **> 3000m**，住宿块海拔标红，且 `tips` 自动补一句"⚠️ 高原注意：老人小孩放慢、别跑跳、多喝水防高反"。示例：四姑娘山 3100、新都桥 3500 自动触发。
- **海拔解析**：从 `hotel` 文本正则提取数字（如 `雪山情民宿(3100)` → 3100）判定，无需额外字段。

## 5. 其余沿用现有流程
路线库多并存、状态(done/planned)、候选路线、✅去过了、syncRoutes 导出同步、PWA/离线、日历 .ics 导入——**全部沿用**，本次只改"每日如何展示 + daily 数据结构新增两个字段"。

## 6. 验收标准
1. 打开「🗺️ 旅行路线」，成都这条以**每日行程卡**呈现（不是一张大表）。
2. 每张卡含：日期/星期/交通方式、**时间轴**、**路线(A→B, X km)**、**住宿(含海拔，>3000 标红)**、**注意事项**。
3. 原"完整表（原始）"可折叠展开，信息不丢。
4. 成都 8 天 `timeline` + `tips` 由雪花补填完毕，高海拔日自动标红+高原提示。
5. 对话说"DayX 调整"仍能改对应卡；「📅 加入 iPhone 日历」每天一个事件不变。
6. `data/routes.json` 与 `app/index.html` ROUTE_SEED 同步（已先清理假数据：删珠海示例、清 demo 链接、成都改 planned）。
7. **可编辑**：每卡「✏️ 编辑模式」开启后，时间轴/路线/住宿/注意事项均可**就地点改 + 增删条目**，改完即时存本地、刷新不丢；提供「📤 导出改动同步给雪花」（复制 JSON 直接发雪花落库）与「↺ 还原原计划」。

## 7. 可编辑能力（洁梅核心诉求：计划赶不上变化，要能随手改）

洁梅原话："可能我最终不是按照计划走的，希望能够快速的让我改掉。" → 路线卡必须**支持工具内就地编辑**，不依赖找雪花改文件。

### 7.1 机制
- **本地叠层（不污染真值源）**：编辑结果存 `localStorage` 键 `radar-route-edit-<routeId>`，工具渲染时**叠层覆盖** `daily[].timeline/route/hotel/tips/place`。真值源 `data/routes.json` 不动，直到洁梅主动"导出同步"。
- **双写回真值源**：洁梅点「📤 导出改动同步给雪花」→ 复制 JSON → 发给雪花（对话或微信）→ 雪花把该 route 的 `daily` 整段覆盖写入 `data/routes.json` + 同步 `app/index.html` 的 `ROUTE_SEED`（保持离线可用）。**这是唯一回写真值源的路径**，避免误改原始计划。

### 7.2 编辑态交互（对齐已交付 demo）
- 顶部「✏️ 编辑模式」开关 → 切换后每卡进入可编辑态，字段变输入框：
  - **时间轴**：每条 {时间, 事项} 独立编辑；条末「✕」删除；区块右上「＋ 加一条」新增。
  - **路线 / 住宿 / 当天地点**：单行输入框，点哪改哪。
  - **注意事项**：每条独立编辑 + 删除 + 「＋ 加一条」。
- **高原标红实时**：编辑住宿时若海拔 > 3000 仍即时标红（正则复用第 4 节逻辑）。
- **自动存**：每次 `oninput` 即写 localStorage，无需"保存"按钮；刷新/重开工具改动都在。
- **「↺ 还原原计划」**：清本地叠层，回到 `data/routes.json` 原始 `daily`（二次确认防误触）。

### 7.3 导出同步JSON 结构
```json
{
  "routeId": "r-chengdu-2026",
  "editedAt": "2026-08-03T14:40:00",
  "days": [ { "date":"2026/10/1", "place":"卧龙", "mode":"行车",
              "timeline":[{"time":"08:00","action":"..."}], "route":"...", "hotel":"...", "tips":["..."] } ]
}
```
雪花收到后：校验 `routeId` 存在 → 用 `days` 覆盖该 route 的 `daily` → 回写 `data/routes.json` + `ROUTE_SEED` → 提示"已同步，下次周更自动带上"。

### 7.4 不做的范围
- 不做"多人协同编辑""版本历史对比"（洁梅一人改，按需还原即可）。
- 不接后端：仍是静态 PWA + localStorage 叠层，导出复制 JSON 给雪花是回写真值源的唯一方式（与心愿单/路线库现有 sync 机制一致）。
