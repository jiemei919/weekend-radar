# 周末雷达 · 整体功能逻辑说明

> 本文档说明「周末雷达」当前（V1.4.3）按什么逻辑执行、做什么事。面向洁梅，用于回顾工具到底在干什么、数据怎么流、两端的同步边界在哪。
> 各功能点的详细变更规则以对应 PRD 为准（见 `docs/` 目录），本文不重抄已有规则，只讲"现在在跑什么"。

---

## 一、它是什么

一个**纯前端 PWA 网页**（无后端），部署在 GitHub Pages：`https://jiemei919.github.io/weekend-radar/app/index.html`。
四个 Tab：**🔥 本周最热**、**🗓️ 下一个假期**、**⭐ 心愿单（含📍去过的地方）**、**🗺️ 旅行路线**。
核心目标：根据洁梅的全家旅行偏好，从候选池里挑出"这周/这个假期适合去哪"，并把"已经去过、不想再去"的地方自动过滤掉。

## 二、数据文件结构（`data/` 是云端真值源）

| 文件 | 作用 | 谁写 |
|---|---|---|
| `data/visited.json` + `app/visited.js` | **权威"已去过"去重库**（165+ 条，含洁梅点评、三档政策） | 雪花侧 `scripts/build_visited.py` 重跑生成，**不**由前端改 |
| `data/candidates.json` + `app/candidates.js` | 19 个候选地 × 13 维偏好向量 | 雪花侧维护 |
| `data/hot-pool.json` + `app/hot-pool.js` | 本周最热候选池（约 49 地 + 各平台推荐帖链接） | 雪花侧维护 |
| `data/taste-profile.json` + `app/taste-profile.js` | 偏好权重真值源（强/顺带/排斥三维） | 雪花侧 + 自学习器 |
| `data/holidays.json` + `app/holidays.js` | 法定节假日与可用日 | 雪花侧维护 |
| `data/wishlist.json` | 洁梅的**心愿单**（想去的目的地，跨假期） | **洁梅前端操作自动同步** |
| `data/routes.json` | 旅行路线库（已走过 + 规划中） | **洁梅前端操作自动同步** |
| `data/confirmed-trip.json` | 已确认行程 | **洁梅前端操作自动同步** |
| `data/leaves.json` | 请假/可用日 | **洁梅前端操作自动同步** |
| `data/feedback-log.json` | 反馈流水（想去/没兴趣/去过了/偏好学习）+ `visited` 用户侧去重叠层 | **洁梅前端操作自动同步** |

> 关键区分：**`visited.json` 是权威库**（跨设备永久拦推荐，需雪花改 `build_visited.py` 重跑）；洁梅在前端点「✅ 去过了 / 📍 记录去过」产生的去重项先存在本地 `VISIT_ADD` + 云端 `feedback-log.visited`，属用户侧真值，需要"跨设备永久拦"时再晋升进权威库。

## 三、雷达同步机制（radar-sync，V1.3.0 起）

**一句话**：洁梅在网页上的任何操作，先写浏览器 `localStorage` → 自动标记"脏" → 15 秒防抖后自动 `PUT` 回 GitHub `data/*.json`（云端真值源）；打开页面时 `pullAll()` 把云端数据并回本地，**本地优先并集**，跨设备一致。

- 同步域映射：`wish→wishlist.json`、`routes→routes.json`、`confirmed→confirmed-trip.json`、`leaves→leaves.json`、`fb/visitedAdd/learn→feedback-log.json`。
- **令牌隔离**：GitHub Personal Token 只存在浏览器 `localStorage`，**不上 git**；换设备需各自粘贴（⚙️ 设置里填）。
- **脏标记持久化**（`LS.syncDirty`）：防止刷新/关页面丢反馈；无令牌时保留待补推，补令牌后自动追上。
- **状态条**（`#syncStat`）：常驻显示「已同步 / 待同步 N / 未配置令牌」。

**本次已验证**：洁梅 2026-08-11 在 Mac 端手工添加「增城白水寨」、标记已去过、填备注、点【立即同步】，数据**已成功写回云端** `data/wishlist.json`（含 `level:中`、备注、`status:done`），并已进入权威 `visited.json` 去重库。功能本身有效。

## 四、已去过去重（三档规则）

推荐生成时，`matchVisitedName` 拿卡片地名去比对「权威库 ∪ VISIT_ADD」，按分隔符拆 token（组合地名也能拦单卡），命中后按政策处理：

| 档 | 含义 | 推荐表现 |
|---|---|---|
| `block` | 永不再推（避雷/明确不去） | 永不作为目的地推荐 |
| `exclude` | 去过默认不推 | 不作为目的地推荐，但可作顺路点出现在已确认行程 |
| `revisit` | 有窗口才推 | 需满足季节/档位/天气窗口，卡片标【复访·理由】 |

**按核心景点去重（V1.4.0）**：每张卡可带 `spots`（核心玩法）。所有核心玩法都去过 → 不推；部分去过 → 保留并标"⚠️ 部分去过"。

## 五、偏好匹配层（决定"推什么"）

`MatchEngine` + `TASTE_PROFILE`（强/顺带/排斥三维权重）+ `LEARN`（洁梅本地反馈的权重 delta）打分。
- 洁梅在卡片点 👍 想去 / 👎 没兴趣 / ✅ 去过了，会经 `learnFromFeedback` 调权重，`saveFb` 落 `feedback-log.json` 参与后续推荐。
- 洁梅给"去过了"的**评分 ≤2 星 → 该地转 `block`（永不再推）**；≥3 星 → `exclude`（默认不推）。这就是"打分参与每周推荐喜好逻辑"的具体落点。

---

## 六、推荐生成与换批

- **🔥 本周最热**：主榜 5–8 张 + 1 张"铄铄彩蛋位"；点【换一批】从 `hot-pool.json` 随机抽 6 张（已去过/已标记没兴趣自动跳过）。
- **🗓️ 下一个假期**：读出下个法定假 → 加请假拼天数 → 【🚀 帮我找目的地】按档位匹配候选 → 【✅ 确认去这里】写 `confirmed-trip.json` 并切到路线库。
- 每张卡可反馈、可【⭐ 收心愿】、【🗺️ 加进路线】、【✅ 去过了】。

## 七、推荐帖链接（V1.4.3 修复）

`hot-pool.json` 里各平台的推荐帖链接，原来多为**桌面端专有/已失效 URL**，导致手机端打不开、Mac 端只开网页版不定位。现新增 `makePostUrl()`，按**平台 + 设备 UA** 重建可用链接：
- 小红书：移动端 `m.xiaohongshu.com/search_result` / 桌面端加 `source=web_search_result_notes`
- 抖音：`www.douyin.com/search/关键词`
- 携程：`you.ctrip.com/globalsearch/?keyword=…&tabType=travelnotes`
- 马蜂窝：`www.mafengwo.cn/search/q.php?q=…`
- 去哪儿：旧接口已下线，降级为百度搜索「关键词 去哪儿」

## 八、📍 记录去过的地方（V1.4.3 新增入口）

在「⭐ 心愿单」Tab 内新增子分区 **📍 去过的地方**，解决"早就去过、现在压根不推的地方反而记不了"的缺口：
- **任意地名**直接记（不限于推荐卡片），填**评分（1–5 星，必选）+ 备注**。
- 保存即：① 写本地 `VISIT_ADD` 立即去重 → ② `saveFb` 落云端 `feedback-log.visited`（评分/备注同步、跨设备保留）→ ③ 重渲染并 `rerenderHot()` 让该地**立刻从本周最热/下一个假期候选里消失**。
- 评分 ≤2 星 → 政策 `block`（永不再推）；≥3 星 → `exclude`（默认不推）。
- 支持编辑（改评分/备注，政策联动）、删除（本地去重移除；若该地已晋升权威库则提示雪花调整）。
- **不打新数据文件、不新开同步通道**，完全复用现有 `VISIT_ADD` + `feedback-log` + `radar-sync`。

## 九、iOS / Mac 两端同步现状与限制

- **读（云端→本地）**：两端打开页面都会 `pullAll()`。Mac 端通常配了令牌走 `raw.githubusercontent`；**iOS 端没令牌时，已改为从 GitHub Pages 公开 URL 只读拉取**，所以 Mac 加的数据 iOS 能看到（心愿单/去过的地方/路线都通）。✅ 本次修复。
- **写（本地→云端）**：**需要各自设备都配 GitHub 令牌**才能上传。iOS 没配令牌 → 在 iOS 上的修改暂不上传（状态条会提示"未配置令牌"）。这是架构限制（令牌只存浏览器，不上 git、不跨设备同步）。
- **结论**：想全端双向同步，在 iOS 的 ⚙️ 设置里也粘贴一次同一枚 GitHub Token 即可。

## 十、旅行路线库（🗺️）

保存"已走过 + 规划中"的行程；每日卡可编辑/导出/还原；支持新建行程、每日费用记录、费用台账（PRD 已出待实装）。与本周最热/下一个假期/心愿单联动（卡片【🗺️ 加进路线】一键生成）。
